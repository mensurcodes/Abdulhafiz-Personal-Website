Hardware Fall 2026, in progress ECE 1100 Discovery Project

FPGA digital lock

A password-protected digital lock built on an Intel DE10-Standard FPGA board. You enter a code with the board's switches and push buttons, and LEDs show whether the lock is locked or unlocked. I chose this as my ECE 1100 Discovery Project to learn FPGA programming, digital logic, and finite-state machine design by building something I could hold and test.

The problem

Locks are everywhere: doors, safes, lockers, and the access panels on buildings. Most electronic locks run on a microcontroller, where software reads the keypad and decides what to do. I wanted to understand how the same behavior can be built directly in hardware, with no processor and no program running line by line. An FPGA lets me describe the lock as digital logic, so every input is checked by circuits that react on each clock cycle. The question I set out to answer was simple: can I design a lock whose entire behavior lives in a finite-state machine, and make it reliable enough to trust?

The process

I started by drawing the lock as a state diagram before writing any code. Each state stands for how much of the code has been entered correctly so far. A correct input moves the machine forward one state, a wrong input sends it back to the start, and reaching the final state unlocks the lock. A reset button returns everything to the locked state at any time.

Next I wrote the design in SystemVerilog in Intel Quartus Prime. I split it into sequential logic, which stores the current state on each clock edge, and combinational logic, which decides the next state from the current state and the inputs. I mapped the inputs and outputs to the board: the switches and push buttons for entering the code and resetting, and the LEDs for showing locked or unlocked.

To check the design, I simulated it before loading it onto the board. I tested the correct code, wrong codes, a wrong entry partway through a correct sequence, and resets in the middle of entry. After simulation, I programmed the FPGA and repeated the same tests by hand on the real hardware.

The outcome

The project is still in progress. So far I have a working state diagram, a SystemVerilog design, and tests for valid and invalid code sequences and for reset behavior, both in simulation and on the board. The biggest lesson has been how much planning matters in hardware: once the state diagram was right, the code followed from it, and most of my bugs came from cases I had not drawn yet. Next, I plan to make the code changeable instead of fixed, add a lockout after too many wrong attempts, and record a demo video of the lock running on the board for the Discovery Project Showcase.

Hardware Aug 2026 – present

RISC-V processor: RTL to physical layout

A 32-bit RV32I processor I took from SystemVerilog to a signed-off layout through Silicon Jackets' digital design, verification, and physical design tracks, in the SkyWater 130 nm process.

  • Design. Built the single-cycle processor in SystemVerilog with SRAM-based instruction and data memory and load-stall control.
  • Verification. Wrote a class-based testbench with a monitor and reference-model scoreboard, plus directed and constrained-random instruction tests. Debugged failures in SimVision waveforms.
  • Physical design. Synthesized to about 7,200 cells, then floorplanned and routed in Cadence Innovus with TCL. Improved total negative slack by 32% with clock gating and high-speed cells.
  • Signoff. Ran DRC and LVS with Cadence Pegasus.

Career goals

I want to build the chips that everything else runs on. My long-term goal is to work in the semiconductor industry as a digital design and design verification engineer: writing the RTL for processor and SoC blocks, and proving that it works before it ever reaches silicon.

Verification is where I learned the most. Writing a testbench for my RISC-V processor showed me how many ways a design can be wrong while still looking right, and how much a good scoreboard and a clear waveform can save. Taking the same design through synthesis and layout taught me that every line of RTL has a cost in timing and area. I want a career where I keep working across that whole path.
